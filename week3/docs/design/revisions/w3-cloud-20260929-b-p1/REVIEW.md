## Implementation rules extracted

1. **No stage.** The canvas, the stage container, `html`/`body` and the Tauri window background become transparent. There is no fill anywhere behind the eye.
2. **Light becomes alpha.** Accumulated particle light maps to straight (unpremultiplied) colour plus alpha = brightness (max channel, soft-clipped as today), so black contributes nothing and the desktop shows through (img-01). Dense regions keep hue rather than turning into an opaque plate. The glow buffer and the supportive light gradient use the same rule, so neither can produce a dark or muddy rectangle over a bright window (img-02).
3. **Pupil = absence of light.** The square pupil stays readable as a gap in the particles. It is never painted dark (img-03 deviation rejected).
4. **Glitch boxes: pure light (owner decision).** Remove the 72% charcoal backing. Stripes, outline and trail are drawn additively, about 1.35× brighter than p3-a2, so the boxes stay visible over the dark wallpaper and read faintly over white (img-03 box grammar). Timing, count and anchoring are unchanged from the approved p3-a2.
5. **Tracking boxes** remain hairline light. Keep the approved pearl tone; the red tint in img-01 is not adopted.
6. **Overlay window config → moved to p2.** Transparent, no decorations, always on top, skip taskbar, no shadow, sized to the monitor. It lands together with drag, click-through and the control pill, so the native window is never left frameless and immovable between passes. It is untestable here either way.
7. **One form, per-particle material (owner, round 2).** *"It should have 1 form, but the particles that overlap the white areas are darker, while the particles that overlap the dark area are lighter."* Form, motion and composition never change with the background. Each particle looks up the brightness directly behind it and blends continuously between **light** (additive emission, rule 2) and **ink** (the same hue deepened toward each emotion's pigment palette: crimson, plum/rose, apricot/gold/coral/mint, gold/coral/magenta, indigo/violet/teal with an amber core), drawn with normal alpha so it darkens what is behind it. A form that straddles a window edge is therefore half light and half ink (img-04). Blending is smoothed over ~0.6 s so moving windows don't flicker it. Glitch stripes and tracking hairlines follow the same per-pixel rule. The square pupil stays an empty gap in both.
8. **Local backdrop sampling (native → p2; renderer interface in p1).** p1 defines the renderer's `LumaGrid` input and a browser test sampler. In p2 a Rust command returns only a **coarse luminance grid** (e.g. 32×18 values) of the screen region under the overlay, at ≤2 Hz. No pixels leave the Rust function, nothing is stored or logged, and it is never sent to a provider. The renderer receives only that grid. In the browser fixture, `?backdrop=desktop` derives the grid from the synthetic review image. The consent/privacy copy changes from "No camera or screen is captured" to an exact statement of this local sample. macOS Screen Recording permission and Windows behaviour need the owner's native test.
9. **Browser review backdrop.** `?backdrop=desktop` puts the synthetic desktop image (p1 img-20) behind the transparent page for review captures only. It is labelled as a test backdrop and is not native evidence.

## Pass p1 critique (agent self-critique, not an owner rating)

- **No stage — met in the renderer.** The canvas, stage and page are transparent; nothing fills behind the eye. A test asserts no full-canvas fill and no charcoal fill through a state transition with glitches.
- **Per-particle light/ink, one form — met in the browser.** On the split backdrop, supportive is indigo/teal ink on the white half and pale light on the dark half; comfort is plum ink turning into rose light at the edge; the congratulation helix is magenta ink / cream light. Form and motion are identical on both sides (img-04/vid-01 intent).
- **Ink reads on white — improved (was the owner's "veil too weak").** The rest eye on white is a crimson ink eye with its square pupil gap (matches img-05). Joy's specks read as warm ink over the white windows.
- **Glitch boxes — pure light / ink, no backing (owner decision).** The stripes are additive light over dark and ink over white, with the page showing between them. Count, timing and anchoring are unchanged from approved p3-a2.
- **Tracking boxes** turn into dark hairlines over white and stay pearl over dark.
- **Regression risk — work coverage.** While the rest eye or comfort sits over a text window, the dense ink **covers the text beneath** (desktop rest still). Pure light used to wash out instead. This is the trade-off of ink. Candidate mitigations for the owner: lighter ink coverage at rest (not while responding), or default placement over darker areas (p2 corner placement helps).
- **Mid-grey areas** (e.g. grey cards) get a partial blend, which looks a little washed out. This is by design (no hard switch); tune after native testing.
- **Performance (headless Chromium 141, not native/GPU):** the capture's synchronous draw reported 31.1 / 45.5 ms (median/p95) vs the baseline capture's 20 / 26.7 ms. A same-load A/B against `f32de6d` in a separate worktree showed no difference (processing 32.4 vs 29.7 ms median; comfort 35.4 vs 36.1 ms), so the capture difference reflects machine load between runs, not this change.
- **Not done in p1 (moved to p2):** native transparent/always-on-top window, drag, click-through, the Rust screen-luma sample, and the privacy-copy change. The fixture's default is now the dark test backdrop, because a transparent page in a plain browser sits on white.
