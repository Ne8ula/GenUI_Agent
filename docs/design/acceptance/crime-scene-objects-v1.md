## Fix round 2 — failed v1 preflight and compiler correction

The coordinator reports one owner-approved CPU preflight for plan `d97615dc5ab764a7dc6a3f3c57ef74362300f44bdc71bbdb9ce6472cbbeb73e1`. The implementation worker read the complete supplied `ffs-th0028-objects-v1/preflight-build.log` and its receipt, but did not submit it. Image `im-MyaG17ZGr0WoZklrnm5RVf` failed at torchmcubes installation. The receipt is `failed-or-uncertain`, with cleanup recording app `ap-xcluck5NXoNtq0ipi2v7sr` stopped and zero tasks. These retained artifacts are not modified by this fix.

- **Observed failure:** log lines 78–96 show successful `c++`/`nvcc` object compilation; line 104 switches to `clang++` for C++ shared linking. The installer's broad catch then retries CPU-only (lines 105–106), which also links with `clang++` and fails because that executable is absent (137–138). This is not evidence that CUDA compilation itself failed.
- **Source-derived cause:** pinned torchmcubes `setup.py` does not assign compiler variables. [PyTorch 2.5.1](https://github.com/pytorch/pytorch/blob/v2.5.1/torch/utils/cpp_extension.py) uses environment `CXX` or default `c++` for Ninja, while its ABI check uses setuptools' `compiler_cxx`. [Setuptools 75.8](https://github.com/pypa/setuptools/blob/v75.8.0/setuptools/_distutils/sysconfig.py) derives `CXX` and `LDCXXSHARED` from Python sysconfig, then applies independent environment overrides. Installed Modal 1.6.1 source confirms `add_python='3.11'` injects standalone Python into `/usr/local`. The observed split identifies inherited Python build configuration, not torchmcubes forcing clang or an exported `CXX=clang++` (which would also change Ninja). No live container environment/sysconfig dump was taken.
- **Smallest correction:** select existing `build-essential` compilers globally before any pip/native build: `CC=gcc`, `CXX=g++`, `LDCXXSHARED='g++ -pthread -shared'`. The explicit linker override is necessary: in pinned setuptools, overriding `CXX` alone does not replace `LDCXXSHARED`. No compiler package or model pin is added/changed; the CUDA-export assertion stays mandatory.
- **Other recipe steps:** pinned SAM 2 returns no native extensions under the existing `SAM2_BUILD_CUDA=0`. PyPI release metadata confirms CPython 3.11 manylinux x86_64 wheels for xatlas 0.0.9 and fast-simplification 0.1.7; normal wheel installation does not compile them. This confirms wheel availability, not which files the remote mirror will select. Global compiler selection also covers any source-build fallback elsewhere in the recipe.
- **Fresh attempt:** `OUTPUT` now points to `.local/reconstruction/ffs-th0028-objects-v2`. V1 keeps the failed receipt/log; no receipt is copied/reset. Prepare a new v2 plan and obtain new finite approval before another preflight. The output-folder version changes, not the plan/result schema kind.
- **Offline RED/GREEN:** the added compiler/linker-environment ordering and v2-folder assertions first produced **Ran 2 tests in 0.121s; FAILED (failures=2)**. After the fix, the full suite passed as recorded below. No new cloud build was attempted.
